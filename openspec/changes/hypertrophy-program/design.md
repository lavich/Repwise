## Context

Мотивация и решения пользователя — в proposal.md. Сейчас:

- Упражнения (`src/domain/exercises.ts`) и программа (`src/domain/program.ts`) описывают 10 упражнений с уровнями 1–4 = неделям; цель подхода берётся из уровня (`prescriptionFor`).
- Прогрессия (`src/domain/progression.ts`) работает по уровням и RPE; состояние упражнения — `{ level, band, useAlternative }`; решения — `ProgressionDecisionKind` (`src/domain/types.ts`), их подписи и цвета — `src/lib/format.ts`, `src/components/SuggestionCard.tsx`.
- Сессия хранит `programWeek`, `level`, `band`, `plannedExerciseId`/`performedExerciseId`; самооценка — `rpe`, `pain`, `dizzinessOrNausea`, `notes`.
- Хранилище (`src/storage/*`) валидирует данные zod-схемой со `schemaVersion: 1`; при ошибке сохраняет строку в `repwise:data:corrupted:<время>`; вкладки синхронизируются через событие `storage` (`src/state/store.ts`).
- Ход тренировки (`src/domain/workoutFlow.ts`) в целом не зависит от состава программы.

## Goals / Non-Goals

**Goals:**
- Одна модель «ступени сопротивления» для лент и вариантов с собственным весом.
- Прогрессия остаётся чистым модулем с тестами; смена ступени — только по подтверждению.
- Формат данных, устойчивый к будущим правкам лестниц ступеней.

**Non-Goals:**
- Миграция истории старой программы — пользователь выбрал чистый лист.
- Подходы на время, разгрузочные недели, питание, раздельный учёт левой и правой стороны.

## Decisions

### 1. Ступени сопротивления с устойчивыми идентификаторами

Упражнение описывает `loadSteps: { id, label, bands: BandLevel[] }[]` — лестницу от лёгкой ступени к тяжёлой — и `defaultStepId`. Лента — частный случай ступени (`bands: ['L2']`); вариант с весом тела — ступень без лент. Состояние прогрессии, подход в сессии и рекомендации хранят `stepId`, а не номер в лестнице: правка лестницы в будущем не перепутает историю. Схема данных проверяет, что `stepId` есть в лестнице своего упражнения.

Альтернативы: номер ступени — компактнее, но ломает историю при любой правке лестницы; лента и вариант раздельно — две оси прогрессии без выгоды для пользователя.

Длина хвата — часть ступени. Замкнутая лента около 1 м (≈ 2 м по окружности) без хвата провисает в части упражнений (румынская тяга, тяги, сгибания), поэтому в исходном положении каждого ленточного упражнения указана фиксированная постановка: ширина стоп и сколько раз намотать ленту на кисти, чтобы в начале движения она была слегка натянута.

Лестницы и стартовые ступени (стартовая — **жирным**):

| Упражнение | Повторы | Ступени |
|---|---|---|
| Приседания с лентой | 8–12 | L1 · **L2** · L3 · L2+L3 |
| Отжимания | 6–12 | от стула · **от пола** · ноги на стуле · с лентой L1 · с лентой L2 |
| Тяга ленты сидя | 10–15 | L1 · **L2** · L3 · L2+L3 |
| Румынская тяга с лентой | 10–15 | L1 · **L2** · L3 · L2+L3 |
| Жим ленты над головой | 8–12 | **L1** · L2 · L3 |
| Сгибания рук с лентой | 10–15 | **L1** · L2 · L3 |
| Подъёмы на носок | 10–15 на ногу | две ноги · **одна нога** · одна нога с паузой |
| Обратные скручивания | 10–15 | **ноги согнуты** · ноги выпрямлены · с медленным опусканием |
| Болгарские выпады | 8–12 на ногу | сплит-присед · **болгарский** · с лентой L1 · с лентой L2 · с лентой L3 |
| Тяга ленты в наклоне | 10–15 | L1 · **L2** · L3 · L2+L3 |
| Сгибания ног со скольжением | 8–12 | **две ноги с удержанием моста** · две ноги полностью · одна нога |
| Разведения рук с лентой | 12–20 | **L1** · L2 |
| Ягодичный мост с лентой | 10–15 | L1 · **L2** · L3 · одна нога с L2 |
| Разгибания рук с лентой над головой | 10–15 | **L1** · L2 · L3 |
| Мёртвый жук | 8–12 на сторону | только ноги · **руки и ноги** · с медленным опусканием |

Отжимания — одно упражнение в обеих тренировках, состояние общее. Мост с L2+L3 не удержать руками, поэтому последняя ступень — на одной ноге.

Альтернатива и замена упражнения больше не нужны, поэтому `plannedExerciseId`/`performedExerciseId` объединяются в `exerciseId`.

### 2. Двойная прогрессия и виды решений

`evaluateExercise` оценивает упражнение по подходам сессии относительно ступени, записанной в этой сессии (а не текущего состояния — оно могло измениться в другой вкладке). Правила — в delta-спецификации `progression`. RPE сессии хранится и показывается, но в решениях не участвует.

Виды решений и подписи:

| Вид | Подпись | Меняет ступень |
|---|---|---|
| `step-up` | «Можно тяжелее» | да, на следующую |
| `step-down` | «Легче» | да, на предыдущую |
| `pain-hold` | «Без повышения» | нет |
| `keep` | «Без изменений» | нет |
| `add-reps` | «Добавляйте повторы» | нет |
| `top-step` | «Максимальная ступень» | нет |
| `bottom-step` | «Начальная ступень» | нет |

Правило 1 (боль) блокирует только повышение: правило «ниже диапазона → легче» после боли продолжает работать.

Повторы на сторону: в упражнениях «на сторону» пользователь вводит повторы слабой стороны; сумма повторов за тренировку считает одну сторону.

Прошлый результат (`lastPerformance`) — последняя завершённая или остановленная сессия, где по этому упражнению на этой ступени записан хотя бы один подход. Значение счётчика по умолчанию для подхода N — повторы подхода N той сессии, а если его нет — нижняя граница диапазона.

### 3. Недельная цель вместо 4 недель

Тренировки A/B чередуются (`nextWorkoutId`). На главной — выполненные тренировки текущей недели (пн–вс, местное время) по времени начала тренировки, как в календаре, из 3, и общий счётчик. Поле `programWeek` удаляется.

### 4. Новый формат данных и чистый лист

`schemaVersion: 2`. При загрузке данные версии 1 переносятся в `repwise:data:v1` (если там пусто), и приложение стартует с начального состояния: настройки по умолчанию (отдых 90 с), `safetyAcknowledged = false` (новые правила показываются заново); тема сохраняется. Незавершённая тренировка старой программы не переносится. Резервная копия версии 1 при импорте отклоняется.

Данные версии 1, пришедшие через событие `storage` после того как приложение уже работает с версией 2 (старая вкладка), игнорируются — иначе старая вкладка затёрла бы новые данные.

### 5. Безопасность

Остаётся: «Стоп», пропуск с причиной (боль, усталость, нет нужной ленты или места, другое), вопрос о боли, запрет повышения после боли и после остановленной тренировки, напоминание перед первой тренировкой: техника важнее числа повторов; остановиться при боли; проверять ленты на надрывы; надёжно фиксировать ленту под стопой и держать её подальше от лица. Удаляется: `dizzinessOrNausea`, причины `dizziness`/`balance`, плашка ограничений, напоминание о переходе на пол, порядок «сначала стоя», тексты про врача в форме завершения и окне «Стоп» (остаётся общий совет обратиться к специалисту при повторяющейся боли). Цвет RPE в форме нейтральный: подходы близко к отказу — норма.

### 6. Иллюстрации и описания

Система поз (`poses.ts`) с двумя кадрами сохраняется; новые позы для 15 упражнений. Советы по постановке включены в исходное положение: полотенце для сгибаний ног — на гладком полу (на ковре — пакет или бумажная тарелка); подъёмы на носок — с края ступеньки или толстой книги для полной амплитуды.

## Risks / Trade-offs

- [Стартовая ступень не подходит пользователю] → «первый подход ниже диапазона → легче» и ручной выбор ступени в библиотеке.
- [Разная длина хвата делает одну ступень несравнимой между тренировками] → фиксированная постановка в исходном положении каждого ленточного упражнения.
- [Скачок нагрузки L3 → L2+L3] → это последняя ступень; дальше — подсказка про темп и паузы.
- [Ввод повторов слабой стороны занижает объём] → осознанно: прогрессия по слабой стороне выравнивает стороны.
- [Старые данные пропадают из интерфейса] → решение пользователя; строка сохраняется в `repwise:data:v1`.

## Migration Plan

Выкатка с новой версией приложения: при первом запуске данные v1 переносятся в `repwise:data:v1`. Откат — предыдущая версия прочитает `repwise:data` как повреждённые данные и начнёт с нуля; данные v2 сохранятся в ключе `corrupted:`, данные v1 — в `repwise:data:v1`.

После архивации изменения обновить разделы Purpose основных спецификаций `safety`, `workout-program`, `progression` и формулировку «уровни» в «Локальное хранение» (delta не меняет Purpose).
